# OpenBot で組む

OpenBot では、エージェントの設定を読み書きする道具を、OpenBot の中のエージェントが持っています。チームを組むときは、差配役か、エージェントを作る役（召喚士）に頼みます。

## 手順

1. レシピの `roles` を見て、作るエージェントを決める。
2. 役割ごとに、次を設定する。
   - **名前**：`role.yaml` の `name`
   - **プロフィール（指示）**：`instructions.md` の全文。最後の「使う人が埋めるところ」を、自分のプロジェクトに合わせて書き足す
   - **モデル**：`role.yaml` の `model_example` を参考に、OpenBot で使えるモデルから選ぶ。このチームで実際に使っている設定（予備のモデルを含む）は `role.yaml` の `openbot` にある。設定を変えたら `openbot` も更新する
   - **アイコン**：`avatar.png`
3. `sections.yaml` のとおりに、サイドバーのセクションに分ける。
4. 役割の `skills` を主候補として、`optional_skills` は `skill_usage` の条件に合うものだけ選ぶ。`openbot.skill_overrides` がある場合は、下の「既存スキルで代替するとき」を確認する。追加する候補は、[`スキルの準備手順`](../skills/README.md) に従って、`catalog.yaml` の固定コミットから必要なファイルとライセンス通知を取得する。ローカルスキルの登録方法・ツール名・参照パスは利用中のOpenBotの版で確かめ、少量の入力で試す。
5. 差配役をリーダーにしたチャンネルを1つ作り、全員を入れる。OpenBot のチャンネルでは、ほかのメンバーはリーダーから仕事を振られるまで動かない。
6. 選んだレシピの `roles`・`rules`・`handoffs` を大賢者に共有する。`handoffs` は成果物の受け渡し先を表し、実際の依頼は大賢者が振り分ける。大賢者の `{{issue_tracker}}` に作業の記録先を設定する。未設定・未接続なら、指示にあるとおり会話内で一時管理する。

## 既存スキルで代替するとき

共通の `skills` と `optional_skills` は、他のアプリでも準備できるOSS候補です。OpenBotですでに使えるスキルが同じ仕事を担当する場合は、`openbot.skill_overrides` に省略の条件を記録しています。

各項目の `skill` は共通カタログの候補、`existing_skill` はOpenBot内で確認する既存スキルの名前です。`action: use_existing_if_available` は、**既存スキルが実際に使え、用途と利用条件を確認できた場合だけ**、同じ仕事をするカタログ候補の追加を省略する指定です。名前が似ているだけでは省略しません。

未導入・用途が合わない・確認できない場合は、`fallback: use_catalog_skill` に従って共通の候補を準備します。条件付きの候補は、その条件に当てはまる場合だけ対象にします。既存スキルの名前は、公開元・版・適用ライセンスを確認した記録ではありません。共通カタログと同じOSS条件だと推定したり、既存スキルの本体を他のアプリへ転載したりする根拠にはしません。

## 気をつけること

- エージェントを作る・変える前に、何が変わるかの一覧を出して、持ち主の確認を取る。
- スキルを入れる前に、ライセンスと中身（とくにスクリプト）を読む。
- 使い魔の `vercel/agent-browser` と `openai/screenshot` はOpenBotでは使わない。Mausbotなど別のアプリ向けの候補。ブラウザ操作はユーザーが明示しない限り内蔵ブラウザ（`openbot_browser`）を使い、画面取得もOpenBotの道具を使う。別のブラウザとはサインインが共有されない。
- 大賢者の `superpowers/dispatching-parallel-agents` は条件付き。OpenBotではチームメイトへの依頼とチャンネルの振り分けを優先し、試してから主候補にするかを決める。
- 権限（ファイルやコマンドへのアクセス、画面操作、自動承認）は、持ち主が決める。

## OSSスキルの確認状況

元の本文とライセンスを確認した候補を記録しています。このアプリでの導入・動作検証はまだです。手順の完了をもって動作確認済みとはせず、候補・アプリの版・試した入力・結果を残します。
